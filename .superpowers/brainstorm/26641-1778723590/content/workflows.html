核心工作流 & 技术要点

1. 笔记保存 → 链接解析流程

保存时发生什么
编辑器提交 Markdown 内容 → 正则提取所有 [[target-slug]] → 查找/创建目标笔记占位 → 更新 links 表（删旧写新） → 更新 FTS 索引 → 保存笔记

关键：链接对应关系完整存储在 links 表中，所以反向链接查询只需一次 SQL JOIN，不需要每次遍历全文。

2. 知识图谱渲染

图谱页面数据流
GET /api/graph → 返回 {nodes: [{id, title, slug}], edges: [{source, target}]} → 前端 D3-force 布局 → 节点大小 = 链接数量（度中心性） → 点击节点 → 跳转 /note/{slug}

3. 全文搜索

中文分词 jieba 分词后写入 FTS5，或使用 simple tokenizer（按字符 bigram）作为轻量替代
结果排序 FTS5 bm25 权重，标题匹配权重高于正文
高亮展示 FTS5 snippet() 函数返回带标记的片段，前端渲染

4. 错误处理 & 边界情况

链接目标不存在 渲染时显示为红色虚线链接，点击可快速创建占位笔记
slug 重复 保存时检查，若重复自动追加 -2, -3 后缀
空内容笔记 允许创建，作为占位符。在列表中标记为「草稿」
图谱节点过多 默认显示最近 N 个节点或限制深度，提供过滤器
数据库备份 SQLite 单文件，定期复制即可备份；提供导出按钮

5. 测试策略

单元测试 链接解析（正则提取 [[link]]）、slug 生成、Markdown 渲染
集成测试 FastAPI TestClient：CRUD 笔记、搜索、图谱 API
前端测试 保持简单——手工验证编辑器、图谱交互，不引入前端测试框架
